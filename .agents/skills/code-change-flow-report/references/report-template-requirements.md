# HTMLテンプレート要件

この資料は、HTMLの見た目と動作についてユーザーと合意した仕様を固定する。HTMLを生成または変更する前に必ず読む。

## 正本と生成方法

- HTMLは`assets/generator/generate-report.mjs`を正本として生成する。
- 過去に生成したHTML、別のコードレビュー用テンプレート、手書きのHTMLへ置き換えない。
- `scripts/generate-report.sh`を使う。このスクリプトはJSON、入れ子、接続線、開閉範囲、生成後HTMLを検査する。
- 生成後HTMLの`code-change-flow-template-version`は`2026.09.12.4`でなければならない。
- CSS、シンタックスハイライト、タブ操作、入れ子開閉処理をHTML内へ埋め込み、単体のHTMLファイルだけで表示できるようにする。
- 外部のCSS、JavaScript、画像、Web API、ローカルサーバーへ依存しない。
- Webサーバー、開発サーバー、HTTPサーバーを起動しない。Node.jsの生成処理はHTMLを書き出した時点で終了させる。

## 表示する処理フロー

- 変更行だけを表示しない。Controllerなどの実際の入口から、変更箇所を通り、レスポンス、保存結果、イベントなどの終点へ到達するまでを表示する。
- 変更箇所への到達と変更結果の理解に必要な未変更コードも表示する。未変更ステップでは`beforeCode`と`afterCode`を同一にする。
- 呼び出し元のコード断片は、呼び出しを行う箇所までで止める。呼び出し先から戻った後の`return`や後続処理を同じ断片へ先に書かない。
- 呼び出し先は`calls`へ入れて1段深く表示する。呼び出しから戻った後の処理は、呼び出し元と同じ段の次ステップとして表示する。
- 入れ子は最大10,000段まで扱う。表示段数を増やすための架空の呼び出しは作らない。
- 1段目同士が実行上つながる場合は線を表示する。つながらない場合は後側のステップへ`connectFromPrevious: false`を設定し、間隔を残したまま線だけを表示しない。

## 表の構成と寸法

- ファイル位置は`{ファイルパス}:{開始行}-{終了行}`の形式で表示する。
- 列は左から`変更前`、`変更後`、`解説`、`備考`の4列にする。
- 画面表示では、変更前を820px、変更後を820px、解説を410px、備考を410px相当とし、表全体を2460pxにする。
- 入れ子になった表も幅を2460pxに保つ。入れ子は表自体を縮めず、左位置だけを64pxずつずらす。
- 列タイトルは本文と同じ14pxにし、タイトル行の高さを26pxにする。背景は薄いグレーにする。
- 表全体へ固定の最小高さを設定しない。コードと説明の量に応じて縦方向へ伸縮させる。
- `処理仕様`だけは画面上の最大高さを536pxにする。内容が536pxを超えた場合は縦スクロールバーを表示する。
- 印刷時は`処理仕様`の高さ制限を解除し、全文を表示する。

## コード表示

- Shikiで言語別のシンタックスハイライトを付ける。`language`が未対応の場合もプレーンテキストとして行単位で表示する。
- 変更前の削除行には`-`を付け、背景を薄い赤にする。
- 変更後の追加行には`+`を付け、背景を薄い緑にする。
- 差分位置を上下でそろえる目的の空行を追加しない。元コードに存在する空行だけを表示する。
- 未変更行には`+`、`-`、差分背景色を付けない。

## 解説と備考

- 解説列は`概説`、`変更理由`、`処理仕様`の順に表示する。
- 値がない場合の表示文は、概説を`{変更内容を1～2文で記載}`、変更理由を`{なぜ変更したか}`、処理仕様を`{変更後どう動くか}`、備考を`{補足事項があれば記載}`とする。
- 未変更ステップの変更理由は、他の文章を加えず`変更なし`とだけ表示する。
- 未変更ステップの概説には「コードは変更されていない」「未変更」などの変更有無を書かず、その処理の役割や意味だけを記載する。
- 処理仕様は、コードの呼び出し順を日本語へ置き換えるだけで終わらせない。その処理が何を成立させるか、どの値がその結果を生むか、外部から確認できる具体例の順に説明する。
- 概説、変更理由、処理仕様、備考では、日本語の句点`。`の直後で改行する。最後の句点の後には空行を作らない。
- 説明文の内容は`explanation-writing.md`の規則に従う。

## 接続線と開閉

- 呼び出し関係は64pxの段下げ、縦線、親の縦線から子テーブル左端まで延びる横線で示す。すべての入れ子段で横線を表示し、線の先端に矢印を付けない。
- 呼び出し先を持つ行だけ、ファイルパスの直前に枠線のないシェブロンを表示する。開いている状態は下向き、閉じている状態は右向きにする。
- 呼び出し先を持たない行にも18pxの空き領域を置き、ファイルパスの開始位置をそろえる。
- シェブロンを閉じた場合、その行の子孫だけを非表示にする。同じ段に戻った後続処理は表示したままにする。
- どの段のシェブロンも独立して開閉できるようにする。
- 印刷時はすべての入れ子を展開する。

## コミットタブ

- 1コミットにつき1タブを作る。複数コミットを1つの差分へまとめない。
- タブにはコミットIDとコミットメッセージを表示する。
- 画面では選択したコミットだけを表示する。印刷時はすべてのコミットを表示する。
- キーボードでタブを切り替える場合、ページ全体の横スクロール位置を動かさない。選択タブが見切れる場合は、コミットタブ欄の内部だけを必要な距離だけ横スクロールする。
- 操作部品はコミットタブと入れ子開閉用シェブロンに限定する。装飾目的のボタンは追加しない。
