# 説明文規則

## 各欄の役割

### 概説

最初の1〜2文で「つまり何が変わったのか」を説明する。未変更ステップでは変更の有無を繰り返さず、そのコードが処理フローで何を担当するかだけを説明する。未変更であることは変更理由欄の`変更なし`で示す。

### 変更理由

変更前に起きていた事実、変更した処理、変更後に得られる結果を因果順に記載する。未変更ステップでは、他の文章を加えず`変更なし`とだけ記載する。表へ含めた理由の説明が必要な場合は備考へ記載する。

### 処理仕様

コードの実行順を日本語へ置き換えるだけで終わらせない。最初に、その処理が業務データ、利用者、後続処理にとって何を意味するかを説明する。次に、入力、判定、状態変化、呼び出し、戻り値のうち、その意味を成立させる要素を因果順に説明する。最後に、具体的な入力値と観測できる結果を1つ示す。例外や分岐がある場合は、条件と結果を対にして記載する。

## 処理仕様を意味中心で書く

処理仕様は、コードを隠して読んでも処理の目的と結果を理解できる文章にする。クラス名、メソッド名、変数名は、意味を説明した後でコードとの対応を示すために使う。

次の順序で記載する。

1. この処理が何を成立させるか、または何を保証するかを説明する。
2. 説明に必要な状態値、データ、利用者などの前提を説明する。
3. どの値または判定が、どの結果を生むかを説明する。
4. 具体的な入力例と、保存内容、レスポンス、ログなど外部から確認できる結果を示す。

次の書き方だけで処理仕様を終えない。

- メソッドAを呼び、次にメソッドBを呼ぶという実行順の列挙。
- クラス名、メソッド名、変数名を日本語の助詞でつないだ説明。
- コードと同じ情報しか持たない逐語的な言い換え。
- 「設定する」「処理する」「連携する」だけで、その結果を示さない説明。

### 悪い例

`OrderServiceはmapper.toEntity(request)でOrderを生成し、order.initializeStatus()で状態をRECEIVEDに設定してから、repository.save(order)を呼び出す。`

この文は呼び出し順を説明しているだけで、RECEIVEDを保存する意味や、後続処理が何を判断できるようになるかを説明していない。

### 良い例

`この処理は、新しく受け付けた注文を「受付済み」として保存し、後続処理が未受付のデータと区別できる状態にする。注文状態とは、注文が受付、出荷、完了などのどの段階にあるかを表す値である。OrderServiceが保存前にRECEIVEDを設定するため、データベースへ登録された時点で注文は受付済みになる。例えば、注文IDが1001の注文を登録直後に照会するとstatusはRECEIVEDとなり、後続の出荷処理はその注文を処理対象として判定できる。`

### 備考

理解に必要な用語、前提、影響範囲、対象外、運用上の注意を記載する。別の欄と同じ内容を繰り返さない。

## 文章の規則

- 最初の1〜2文で「つまり何なのか」を説明する。概説では変更または未変更ステップの役割を、処理仕様では変更後の処理が持つ意味を先に示す。
- 専門用語を使う場合は、その用語がこの処理で何を指すかを説明する。
- 抽象語だけで説明しない。
- 「AによってBが可能になる」と書く場合は、Aのどの値または処理がBを成立させるかを説明する。
- 主語を省略せず、「誰または何が、何を、どうする」の形を基本にする。
- 説明に必要な前提を、その前提を使う文より先に記載する。
- 抽象的な説明の直後に具体例を1つ記載する。
- 1つの文で複数の概念を説明せず、概念ごとに文を分ける。
- 「柔軟」「高度」「効率的」「最適化」など、結果を測定できない形容を避ける。
- 結論までの原因、処理、結果を省略しない。
- クラス名、フレームワーク名、設計用語を羅列して説明を終えない。

## 未変更ステップの記載例

- 概説: `OrderControllerはHTTPリクエストを受け取り、注文データをOrderServiceへ渡す入口である。`
- 変更理由: `変更なし`
- 処理仕様: `この処理は、API利用者が送った注文を業務処理へ渡し、登録結果が確定してから応答する入口である。OrderControllerがOrderServiceの完了を待つため、保存前の未確定な注文を成功結果として返さない。例えば、保存処理が失敗した場合、OrderControllerは成功レスポンスを返さず、既存の例外処理へ制御を渡す。`
- 備考: `Controllerとは、この処理ではHTTPリクエストをJavaメソッドへ受け渡すクラスを指す。`

## 「分からない」と指摘された場合

同じ説明の単語だけを置き換えない。対象処理を入力、前提条件、判定、中間値、呼び出し先、戻り値に分割する。各項目を別の文または別のテーブルとして示し、具体的な変数名と値の例を追加する。
