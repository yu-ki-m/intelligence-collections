# 検証項目

## Gitとコード

- 各コミットが正しい親コミットと比較されている。
- 差分の各変更ハンクが少なくとも1つのテーブルへ含まれている。
- コード断片が親コミットまたは対象コミットの実コードと一致している。
- ファイルパスと行番号がコード断片を指している。
- 未変更ステップの`beforeCode`と`afterCode`が一致している。
- 検証処理が未変更ステップなしと通知した場合は、入口から終点までを再調査している。未変更ステップが不要と判断した場合は、その根拠を最終回答へ記載する。

## 処理フロー

- 各1段目がControllerなどの実際の入口から始まっている。
- 入口から変更箇所まで、値と制御の受け渡しを追跡できる。
- 変更箇所からレスポンス、保存結果、イベントなどの終点までを追跡できる。
- 呼び出し先が`calls`内へ入り、戻り後の処理が親階層の次ステップへ戻っている。
- 実行上つながらない1段目に`connectFromPrevious: false`が設定されている。
- 変更と関係しないコードが表を埋める目的で追加されていない。

## 説明

- 概説の最初の1〜2文だけで変更または未変更ステップの役割を把握できる。
- 未変更ステップの概説が変更有無を繰り返さず、処理の役割や意味だけを説明している。
- 専門用語が最初に使われる箇所で説明されている。
- 各文に主体、対象、動作が記載されている。
- 原因、処理、結果の順序が飛んでいない。
- 抽象的な説明の直後に変数名、条件値、レスポンスなどの例がある。
- 未変更ステップの変更理由欄が`変更なし`の5文字だけになっている。
- 処理仕様の最初に、その処理が業務データ、利用者、後続処理にとって持つ意味が説明されている。
- コードを隠して処理仕様だけを読んでも、前提、因果関係、観測できる結果を理解できる。
- 処理仕様がクラス名、メソッド名、変数名と呼び出し順の列挙だけで終わっていない。

## 生成物

次のコマンドが成功することを確認する。

```bash
bash <skill-root>/scripts/generate-report.sh <review-data.json> <review-report.html>
```

生成したHTMLについて次を確認する。

- HTMLが外部のCSS、JavaScript、画像、Web APIを参照せず、単体ファイルとして開ける。
- HTML生成後にサーバープロセスを残さず、ポートを待ち受けない。
- `code-change-flow-template-version`が`2026.09.12.4`である。
- コミットタブがコミット数と一致する。
- ファイル位置が`{ファイルパス}:{開始行}-{終了行}`の形式で表示される。
- 列が`変更前`、`変更後`、`解説`、`備考`の4列であり、コード列が説明列の2倍の横幅である。
- 表が内容に応じて縦方向へ伸縮し、処理仕様だけが536pxを超えた場合にスクロールする。
- 削除行に`-`と薄赤色、追加行に`+`と薄緑色が付く。
- 未変更行に差分色が付かない。
- 入れ子の矢印がファイルパス左側にあり、配下だけを開閉する。
- 親の縦線から子テーブル左端までの横線がすべての入れ子段にあり、線の先端に矢印がない。
- 独立した1段目の直前に接続線がない。
- タブ切り替え時にページ全体の横スクロール位置が変わらず、コミットタブ欄だけがスクロールする。
- 概説、変更理由、処理仕様、備考が句点ごとに改行される。
- 印刷時にすべてのコミットと入れ子が展開される。

`scripts/generate-report.sh`は、生成後に`scripts/verify-generated-report.mjs`を実行する。最後に`HTML verification passed`が表示されない場合は、生成物を完成扱いにしない。
