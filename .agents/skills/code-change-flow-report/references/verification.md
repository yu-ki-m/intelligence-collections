# 検証項目

## Gitとコード

- 各コミットが正しい親コミットと比較されている。
- 差分の各変更ハンクが少なくとも1つのテーブルへ含まれている。
- コード断片が親コミットまたは対象コミットの実コードと一致している。
- ファイルパスと行番号がコード断片を指している。
- `analysisMode`が`callers`の各変更対象について、意味解析と別系統の検索を実行し、検出した呼び出し箇所IDを`evidence`へ記録している。
- 各探索根拠の呼び出し箇所IDと`callSites`が一致している。
- 未変更ステップの`beforeCode`と`afterCode`が一致している。
- 検証処理が未変更ステップなしと通知した場合は、入口から終点までを再調査している。未変更ステップが不要と判断した場合は、その根拠を最終回答へ記載する。

## 処理フロー

- 各1段目がControllerなどの実際の入口から始まっている。
- コミット先頭と各`connectFromPrevious: false`のステップに`flowTitle`があり、それ以外のステップにはない。
- 複数の第1階層テーブルまたは入れ子を含む処理フローに`flowDescription`があり、単独テーブルにはない。
- 入口から変更箇所まで、値と制御の受け渡しを追跡できる。
- 変更箇所からレスポンス、保存結果、イベントなどの終点までを追跡できる。
- 呼び出し先が`calls`内へ入り、戻り後の処理が親階層の次ステップへ戻っている。
- 各`[後続処理確認]`について、呼び出し元メソッドを呼び出し行から終了まで実コードで確認している。
- 呼び出し後の文がある場合、親階層の次テーブルが同じファイル・同じメソッドの後続行を示し、線で接続されている。
- 接続された後続テーブルがない場合、直接`return`、メソッド末尾、例外終了、非同期境界などの根拠を実コードで確認している。
- 実行上つながらない1段目に`connectFromPrevious: false`が設定されている。
- 各`included`が、同じフロー内の入口ステップ、呼び出し元ステップ、変更ステップを参照している。
- 複数の呼び出し元がある場合、呼び出し箇所ごとに異なる変更ステップが入れ子として配置されている。
- `excluded`にはコードに基づく除外理由があり、`unresolved`が残っていない。
- 変更と関係しないコードが表を埋める目的で追加されていない。

## 説明

- 各コミットの概要が最初の1〜2文で変更全体の結果を説明している。
- 各コミットの概要が必要な前提、変更箇所間の因果関係、`例えば`で始まる具体例を説明している。
- 各コミットの概要がファイル名、クラス名、メソッド名、変更件数の列挙だけで終わっていない。
- 概説の最初の1〜2文だけで変更または未変更ステップの役割を把握できる。
- 未変更ステップの概説が変更有無を繰り返さず、処理の役割や意味だけを説明している。
- 専門用語が最初に使われる箇所で説明されている。
- 各文に主体、対象、動作が記載されている。
- 原因、処理、結果の順序が飛んでいない。
- 抽象的な説明の直後に変数名、条件値、レスポンスなどの例がある。
- 未変更ステップの変更理由欄が`変更なし`の5文字だけになっている。
- 処理仕様の最初に、その処理が業務データ、利用者、後続処理にとって持つ意味が説明されている。
- コードを隠して処理仕様だけを読んでも、前提、因果関係、観測できる結果を理解できる。
- 処理仕様がクラス名、メソッド名、変数名と呼び出し順の列挙だけで終わっていない。

## 生成物

次のコマンドが成功することを確認する。

```bash
bash <skill-root>/scripts/generate-report.sh <review-data.json> <review-report.html>
```

コマンド出力に`Root section self-test passed`、`Caller coverage self-test passed`、`Caller coverage passed`、`Continuation structure self-test passed`、`Continuation structure passed`、`HTML verification passed`が含まれることを確認する。第1階層検査はタイトルと説明の必須条件、単独テーブルの説明禁止、表示単位の境界を検査する。呼び出し元検査は複数呼び出し元、探索結果の未登録、変更ステップの不正共有、未解決、理由のない除外、探索方法の不足、同一箇所の重複登録を検出する。後続処理の構造検査は、接続された後続テーブルのファイルと行順を検査し、実コード・HTMLと照合する対象を`[後続処理確認]`として列挙する。

生成したHTMLについて次を確認する。

- HTMLが外部のCSS、JavaScript、画像、Web APIを参照せず、単体ファイルとして開ける。
- HTML生成後にサーバープロセスを残さず、ポートを待ち受けない。
- `code-change-flow-template-version`が`2026.09.12.14`である。
- コミットタブがコミット数と一致する。
- 各コミットの`概要`がコミット情報の直下かつ最初の比較表より前にある。
- 第1階層の各開始テーブルの直前にタイトルがあり、処理フローだけに説明が表示される。
- 第1階層のタイトルが比較表と同じ横幅を持ち、グレー背景と左罫線で他の領域から区別できる。
- コミット概要は240pxを超えた場合に縦スクロールし、印刷時は高さ制限を解除する。
- ファイル位置が`{ファイルパス}:{開始行}-{終了行}`の形式で表示される。
- 列が`解説`、`変更前`、`変更後`、`備考`の順であり、コード列が説明列の2倍の横幅である。
- 画面背景、比較表、コード欄、列タイトルの明度差によって、コミット、ファイル、各列の境界を判別できる。
- 選択中のコミットだけが青で強調され、差分を示す薄赤色と薄緑色が操作状態へ流用されていない。
- 比較表の二層の影が表の輪郭と背景からの分離を示し、印刷時には解除される。
- 表が内容に応じて縦方向へ伸縮し、処理仕様だけが536pxを超えた場合にスクロールする。
- 削除行に`-`と薄赤色、追加行に`+`と薄緑色が付く。
- 未変更行に差分色が付かない。
- 入れ子の矢印がファイルパス左側にあり、配下だけを開閉する。
- 親の縦線から子テーブル左端までの横線がすべての入れ子段にあり、線の先端に矢印がない。
- 縦の接続線が点線であり、呼び出し先テーブルの直前だけは前のテーブルの下端から横線へ到達するまで連続した実線である。
- 横線を通過した後に入れ子テーブルの横へ続く縦線が点線へ戻り、子テーブルへ張り出す横線が実線である。
- 入れ子を展開すると、呼び出し後の処理が子テーブルの終了後に親階層へ戻って表示され、親階層の接続線が後続テーブルまで続く。
- 独立した1段目の直前に接続線がない。
- タブ切り替え時にページ全体の横スクロール位置が変わらず、コミットタブ欄だけがスクロールする。
- コミット概要、概説、変更理由、処理仕様、備考が句点ごとに改行される。
- 印刷時にすべてのコミットと入れ子が展開される。

`scripts/generate-report.sh`は、HTML生成前に`scripts/verify-caller-coverage.mjs`と`scripts/verify-continuation-structure.mjs`を実行し、生成後に`scripts/verify-generated-report.mjs`を実行する。`Caller coverage passed`、`Continuation structure passed`、`HTML verification passed`のいずれかが表示されない場合は、生成物を完成扱いにしない。最終回答には後続処理を検証した呼び出し件数、後続あり件数、後続なし件数を記載する。
