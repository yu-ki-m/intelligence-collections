# HTMLテンプレート要件

この資料は、HTMLの見た目と動作についてユーザーと合意した仕様を固定する。HTMLを生成または変更する前に必ず読む。

## 正本と生成方法

- HTMLは`assets/generator/generate-report.mjs`を正本として生成する。
- 過去に生成したHTML、別のコードレビュー用テンプレート、手書きのHTMLへ置き換えない。
- 実行状態が`ready-for-generation`になった後、状態ファイルを第3引数に渡して`scripts/generate-report.sh`を使う。このスクリプトは実Gitとコード位置、証跡、JSON、呼び出し元網羅性、呼び出し後の構造、入れ子、接続線、開閉範囲、生成後HTMLを検査する。
- HTMLは最終出力先と同じディレクトリの一時ファイルへ生成する。全検査が成功した場合だけrenameし、失敗時は既存の完成HTMLを上書きしない。
- HTML生成後の状態は`awaiting-final-review`とする。実画面確認の証跡を保存し、現在のHTMLのSHA-256を含む完成ゲートが成功するまで`completed`にしない。
- レポートJSONの`orchestration`は調査と独立検証の内部記録であり、HTML本文、タブ、印刷結果へ表示しない。
- 生成後HTMLの`code-change-flow-template-version`は`2026.09.13.3`でなければならない。
- CSS、シンタックスハイライト、タブ操作、入れ子開閉処理をHTML内へ埋め込み、単体のHTMLファイルだけで表示できるようにする。
- 外部のCSS、JavaScript、画像、Web API、ローカルサーバーへ依存しない。
- Webサーバー、開発サーバー、HTTPサーバーを起動しない。Node.jsの生成処理はHTMLを書き出した時点で終了させる。

## 表示する処理フロー

- 変更行だけを表示しない。Controllerなどの実際の入口から、変更箇所を通り、レスポンス、保存結果、イベントなどの終点へ到達するまでを表示する。
- 変更箇所への到達と変更結果の理解に必要な未変更コードも表示する。未変更ステップでは`beforeCode`と`afterCode`を同一にする。
- 呼び出し元のコード断片は、呼び出しを行う箇所までで止める。呼び出し先から戻った後の`return`や後続処理を同じ断片へ先に書かない。
- 呼び出し先は`calls`へ入れて1段深く表示する。呼び出しから戻った後の処理は、呼び出し元と同じ段の次ステップとして表示する。
- 入れ子は最大10,000段まで扱う。表示段数を増やすための架空の呼び出しは作らない。
- 1段目同士が実行上つながる場合は線を表示する。つながらない場合は後側のステップへ`connectFromPrevious: false`を設定し、間隔を残したまま線だけを表示しない。
- コミット先頭と`connectFromPrevious: false`の第1階層テーブルの直前に`flowTitle`を表示する。複数の第1階層テーブルまたは入れ子を含む処理フローでは`flowDescription`も表示し、単独テーブルではタイトルだけを表示する。

## 表の構成と寸法

- ファイル位置は`{ファイルパス}:{開始行}-{終了行}`の形式で表示する。
- `afterCode`が空でなければ対象コミット側、純粋な削除で`afterCode`が空なら親コミット側の実コードをファイル位置の基準にする。全テーブルのパスと行範囲を実コードと照合し、不一致と未解決を0件にしてからHTMLを生成する。
- 列は左から`解説`、`変更前`、`変更後`、`備考`の4列にする。
- 画面表示では、解説を410px、変更前を820px、変更後を820px、備考を410px相当とし、表全体を2460pxにする。
- 入れ子になった表も幅を2460pxに保つ。入れ子は表自体を縮めず、左位置だけを64pxずつずらす。
- 列タイトルは本文と同じ14pxにし、タイトル行の高さを26pxにする。背景は薄いグレーにする。
- 表全体へ固定の最小高さを設定しない。コードと説明の量に応じて縦方向へ伸縮させる。
- `処理仕様`だけは画面上の最大高さを536pxにする。内容が536pxを超えた場合は縦スクロールバーを表示する。
- 印刷時は`処理仕様`の高さ制限を解除し、全文を表示する。

## 視覚設計

- 画面全体は薄い青みのグレー、比較表は白、コード欄は白に近いグレーにし、長時間読んでも列の境界を見失いにくい配色にする。
- コミットタブの選択状態だけに青を使い、未選択のタブは無彩色にする。差分の赤と緑を、操作状態を示す色として流用しない。
- コミット概要、ファイル位置、列タイトル、本文の順に視線が移るように、背景色と文字の太さを段階的に変える。
- 各比較表には小さい角丸と二層の影を付ける。近い影は表の輪郭を示し、広い影は薄いグレーの画面背景から表を分離する。影を差分色より目立たせず、グラデーションや装飾だけを目的とした色は使わない。
- ファイル位置は等幅フォントで表示し、比較表の一部であることが分かるように表の上辺へ接続する。
- 第1階層のタイトルは比較表と同じ横幅にし、グレー背景と左罫線でコミット概要およびファイル位置から区別する。処理フローの説明はタイトル直下に表示し、本文の行幅を1200px以下にする。
- 縦方向の余白は増やさない。コードと文章の実量に応じて高さを決め、説明本文へ固定の最小高さを設けない。
- 接続線は表の境界線より少し濃くし、入れ子の経路と表の罫線を見分けられるようにする。
- 印刷時は画面用の影と角丸を外し、白背景と罫線だけで内容を判別できるようにする。

## コード表示

- Shikiで言語別のシンタックスハイライトを付ける。`language`が未対応の場合もプレーンテキストとして行単位で表示する。
- 変更前の削除行には`-`を付け、背景を薄い赤にする。
- 変更後の追加行には`+`を付け、背景を薄い緑にする。
- 差分位置を上下でそろえる目的の空行を追加しない。元コードに存在する空行だけを表示する。
- 未変更行には`+`、`-`、差分背景色を付けない。

## 解説と備考

- 各コミットのコミット情報直下かつ最初の比較表より前に、`概要`というラベルでコミット全体の説明を表示する。
- コミット概要の本文は読みやすい行幅に制限し、画面上の最大高さを240pxにする。本文が240pxを超えた場合だけ縦スクロールバーを表示する。
- 印刷時はコミット概要の高さ制限を解除し、全文を表示する。
- コミット概要の文章は`explanation-writing.md`先頭の原文プロンプトとコミット全体の概要に従う。具体例へ`例えば`という語を強制しない。
- 解説列は`概説`、`変更理由`、`処理仕様`の順に表示する。
- 値がない場合の表示文は、概説を`{変更内容を1～2文で記載}`、変更理由を`{なぜ変更したか}`、処理仕様の要点を`{変更後どう動くか}`、手順を`{手順1を記載}`と`{手順2を記載}`、備考を`{補足事項、懸念点、バグ、考慮漏れがあれば記載}`とする。任意の具体例がない場合は、空の具体例欄や代替文を表示しない。
- 未変更ステップの変更理由は、他の文章を加えず`変更なし`とだけ表示する。
- 未変更ステップの概説には「コードは変更されていない」「未変更」などの変更有無を書かず、その処理の役割や意味だけを記載する。
- 処理仕様は、処理の意味を示す要点、`1.`、`2.`と連番を付けた2件以上の手順、必要な場合の具体例の順に表示する。番号はHTMLの`ol`要素で表示する。
- 各番号は、1つの入力、判定、状態変化、呼び出し、戻り値または外部結果だけを扱う。各番号では、主体、扱う値、動作、直後の結果を説明し、コードの呼び出し順だけを日本語へ置き換えない。
- 備考には、用語、前提、影響範囲、対象外、運用上の注意に加え、コード上の根拠がある懸念点、バグ、考慮漏れを記載する。指摘には分類、根拠、発生条件、影響、必要な確認または対応を含め、確認できていない内容をバグと断定しない。
- コミット概要、概説、変更理由、処理仕様の要点・各手順・具体例、備考では、日本語の句点`。`の直後で改行する。最後の句点の後には空行を作らない。
- 説明文の内容は`explanation-writing.md`先頭の原文プロンプトを省略、要約、言い換えせず適用する。

## 接続線と開閉

- 呼び出し関係は64pxの段下げで示す。縦の接続線は点線にする。ただし、呼び出し先テーブルの直前では、前のテーブルの下端からテーブル間の余白とファイル位置の見出しを通り、横線へ到達するまでの縦区間を連続した実線にする。横線を通過した後に入れ子テーブルの横へ続く縦線は点線へ戻す。親の縦線から子テーブル左端まで延びる横線は実線にする。すべての入れ子段で同じ線種を適用し、線の先端に矢印を付けない。
- 呼び出し先を持つ行だけ、ファイルパスの直前に枠線のないシェブロンを表示する。開いている状態は下向き、閉じている状態は右向きにする。
- 呼び出し先を持たない行にも18pxの空き領域を置き、ファイルパスの開始位置をそろえる。
- シェブロンを閉じた場合、その行の子孫だけを非表示にする。同じ段に戻った後続処理は表示したままにする。
- どの段のシェブロンも独立して開閉できるようにする。
- 印刷時はすべての入れ子を展開する。

## コミットタブ

- 1コミットにつき1タブを作る。複数コミットを1つの差分へまとめない。
- タブにはコミットIDとコミットメッセージを表示する。
- 画面では選択したコミットだけを表示する。印刷時はすべてのコミットを表示する。
- キーボードでタブを切り替える場合、ページ全体の横スクロール位置を動かさない。選択タブが見切れる場合は、コミットタブ欄の内部だけを必要な距離だけ横スクロールする。
- 操作部品はコミットタブと入れ子開閉用シェブロンに限定する。装飾目的のボタンは追加しない。
