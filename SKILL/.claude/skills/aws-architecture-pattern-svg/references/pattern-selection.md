# パターン選定・技術調査

## 評価のゲート

必須条件: AWSとして成立する、必要前提が明示可能、特定の実務課題を解決する、構成中に最低1つの有用な設計上の発見がある。

ゲートを満たした候補のみ、下記を各5段階で評価する。

| 評価軸 | 目安 |
|---|---|
| 発見性 | 機能・接続・マネージド化の新しい学びがある |
| 実用性 | ビジネス/運用/設計上の採用動機が明確 |
| 経路の説明可能性 | 図にして因果関係・境界・制約を教えられる |
| 技術の幅 | これまでに選んだパターンと知識が重複しない |
| 導入の現実性 | 設定/コスト/可用性/セキュリティのトレードオフを示せる |

最新性は加点材料の1つにとどめる。重大な仕様不整合は点数で相殺できない。

## 技術領域の候補

ネットワーク、API統合、コンテナ、サーバーレス、非同期・イベント駆動、認証・認可、データ同期・ストリーミング、ストレージ/CDN、オブザーバビリティ・運用自動化、クロスアカウント/マルチリージョン。

特に好ましいのは「従来はLambda/専用サーバー/大量の連携コードが必要だったものを直接統合で置き換える」「公開不要のPrivateLink・VPC Link等で経路を成立させる」「新しく追加された機能が従来の構成の冗長さを減らす」等の学び。

## 発見性が期待できる候補テーマ（採用は現在仕様を検証してから）

- Amazon API Gateway の private integration における VPC Link、ALB/NLB、HTTP APIとREST APIの違い。
- EventBridge Pipes によるイベントソースのフィルタリング・拡張・ターゲット配送。
- DynamoDB Streamsの変更イベントとコンシューマー設計。
- AWS PrivateLinkでコンシューマーVPCからサービス提供側VPCに接続する構成。
- CloudFrontとプライベートオリジン、S3 OAC、キャッシュ・認可の関係。
- Step Functions のサービス統合によるオーケストレーション。
- クロスアカウントのイベント連携と権限境界。
- マルチリージョンの複製・切替、整合性制約、フェイルオーバー。

上記は固定の採用リストではない。新しい候補を継続的に探す。

## AWSの一次資料を調べる

優先: `https://docs.aws.amazon.com/`、`https://aws.amazon.com/new/`、AWS公式ブログ。GA、Region、対応API種別、専用エンドポイント、前提条件、制限、更新日を確認する。網羅できない場合は確認範囲を明示。公式サイトへアクセス不能ならリリース日の断定や独自のURL創作をしない。

## 件数配分

5件なら通常「中級4件/上級1件」「最近の機能を実質的に使うパターン1件」を標準とする。最近の機能が特に重要な場合に2件まで許容。数合わせは禁止。テーマが狭い場合は多様性より正確性を優先。
