# 悪い出力例

以下は、本Skillで **出してはいけない** 出力の例である。架空のAI分類APIについて「マーケティング戦略を考えて」と依頼されたときの、典型的な失敗を示す。

---

> ## マーケティング戦略
>
> **キャッチコピー:** 「世界最速のAI分類API。あなたのビジネスを次のレベルへ」
>
> **ターゲット:** AIを活用したいすべての企業
>
> **施策:**
> 1. X（Twitter）でインフルエンサーに紹介してもらう
> 2. Product Huntでローンチする
> 3. 技術ブログを毎週更新する
> 4. 無料トライアルを提供する
>
> **強み:** 競合より10倍速く、コストは90%削減できます。多くの企業がすでに導入を検討しています。
>
> **競合:** OpenAIやGoogleの製品より優れています。
>
> **市場:** 競合がまだいない、未開拓のブルーオーシャンです。

---

## 何が悪いのか

| 問題 | 該当箇所 | 本Skillのどの原則に反するか |
| --- | --- | --- |
| 製品から始めている | 問題の分析がなく、いきなりキャッチコピーと施策 | 2.1 製品から始めない |
| 問題が再定義されていない | 「速い」という機能の説明だけ | P2 Problem Discovery |
| 市場定義の判定がない | 「AI分類API」という既存カテゴリーのまま、なぜそうするのかの説明がない | P6 Category Decision |
| ICPがない | 「すべての企業」 | P5 ICP & Beachhead |
| 数値の条件がない | 「10倍速く」「90%削減」の比較対象・条件がない | P11 Quantitative Hook |
| 数値・事実を捏造している | 「多くの企業がすでに導入を検討」に根拠がない | 3.2 捏造の禁止 |
| 調べずに「未開拓」と断言している | 「競合がまだいない、未開拓のブルーオーシャン」に、調査の記録がない。実際には汎用の分類器や、LLMの構造化出力機能が先行事例として存在しうる | P0.5 Prior Art Sweep、3.4 「存在しない」という主張の基準 |
| 企業名を敵にしている | 「OpenAIやGoogleより優れている」 | P4 Enemy |
| 証拠ラベルがない | すべての主張が事実のように書かれている | 3.3 証拠ラベル |
| 施策が汎用的 | どの製品にも当てはまる施策の羅列。なぜそのチャネルなのかがない | P21 Distribution |
| 事業性・防御の検討がない | 大手がコピーしたらどうなるか、採算が合うかに触れていない | P27, P28 |
| 次の検証がない | 何が未確認で、何から確かめるべきかがわからない | P32 Next Experiments |

## 改善の方向

同じ依頼に対しては、まず **P0 Intake** で「顧客は今どうやって分類しているか」「現状の性能とコストの実測値はあるか」を確認する。必須項目が欠けていれば、分析を始める前に質問する（`SKILL.md` 3.1）。次に **P0.5 Prior Art Sweep** で既存の解決策を確かめる。依頼は「戦略を」考えるものなので、モードは Full Strategy になる（`SKILL.md` 1章）。証拠ラベル、先行事例の表、反証パス、判断ルールつきの実験表の書き方は、`examples/good-output-jev.md` を参考にする。
