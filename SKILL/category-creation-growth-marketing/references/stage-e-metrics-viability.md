# Stage E: 計測と事業性（P26〜P27）

Stage E では、話題になったことを事業の成果と取り違えないための指標を決め、戦略が事業として成り立つかを数値で確かめる。

---

## P26: Adoption Funnel & Metrics

### 目的

顧客が製品を知ってから、使い続け、他の人に勧めるまでの各段階を別々に測る。段階を分けて測らないと、どこで顧客が離れているのかがわからず、改善する場所を間違える。**SNSのView数を事業の成功とみなしてはいけない。**

### 入力

P18の Motion、P20のローンチの成功の基準、P22の最初の価値の定義、P24の Loop。

### 手順

**Step 1. Funnel の段階を定義する**

```text
Awareness・Interest → Trial → Activation → Adoption → Retention → Commercial → Expansion → Advocacy・Ecosystem
```

Commercial（有料化・受注）の位置は Motion によって変わる（例: Sales-Led では、PoC の成功の直後に受注が来る）。各段階について、「どの行動をしたら、その段階に入ったとみなすか」を定義する。定義があいまいだと、指標が都合よく解釈される。

| 段階 | 定義（例） |
| --- | --- |
| Trial | APIキーを発行した |
| Activation | 自分の入力で最初の判断結果を得た（P22の最初の価値と同じ） |
| Adoption | 2週連続で、週100回以上判断を実行した |
| Retention | 登録から30日後も、週1回以上使っている |

**Step 2. Activation の定義を検証する**

Activation の定義は、**その行動をした人が、その後も使い続ける** ことと結びついている必要がある。ローンチ後は、以下で定義を検証する。

* Activation に達した人と達しなかった人で、30日後の継続率を比べる。
* 差が小さい場合、Activation の定義が本当の価値体験を表していない。定義を見直す。

**Step 3. 指標と目標を決める**

段階ごとに、主な指標と目標値（または目標の決め方）を書く。P18の Motion に合わせて指標を選ぶ。

| 段階 | PLG・Developer向けの例 | Sales-Led向けの例 |
| --- | --- | --- |
| Awareness・Interest | Impressions、検索ボリューム、SNSでの言及、直接流入 | 問い合わせ数、ウェビナー参加者 |
| Trial | Signup、APIキー発行、最初のAPI呼び出し、インストール | 商談化数、PoC開始数 |
| Activation | Time-to-First-Value、最初に成功したワークフロー | PoCの成功基準達成率 |
| Adoption | WAU、MAU、API利用量、アクティブな組織数 | 受注数、導入部門数 |
| Retention | D7 / D30 / D90、繰り返し利用 | 更新率、利用継続率 |
| Commercial | 有料転換率、ARR、ARPA、従量課金の売上 | ACV、セールスサイクル、受注率 |
| Expansion | 席数・利用量の増加、NRR | 追加部門への展開、アップセル |
| Advocacy・Ecosystem | 紹介・共有の数、Integration数、サードパーティのパッケージ、チュートリアル、GitHubリポジトリ、コミュニティのプロジェクト | 紹介経由の商談、事例への協力、パートナー数、SI経由の案件 |

目標値は、以下の順で根拠を探す。

1. 自社の過去のデータ
2. 同じ市場・同じ Motion の公開データ（出典を書く）
3. 上記がない場合は仮置きし、[仮説] として最初の数か月のデータで見直す

**Step 4. 先行指標と遅行指標を分ける**

| 種類 | 例 | 使い方 |
| --- | --- | --- |
| 先行指標 | Activation率、週次の利用量の伸び | 毎週見て、すぐに施策を変える |
| 遅行指標 | ARR、NRR、解約率 | 月次・四半期で見て、戦略を評価する |

**Step 5. コホートで見る**

全体の数値ではなく、登録した時期ごと（コホート）に分けて継続率を見る。全体の数値は、新規の登録が多いと良く見えてしまう。

```text
例: 9月第1週に登録した人のうち、
    1週後に使っている割合 / 4週後 / 12週後
```

継続率の曲線が、ある時点で横ばいになる（下がり続けない）ことが、製品が一部の顧客に定着している証拠になる。

**Step 6. North Star Metric を選ぶ**

「顧客が価値を得たこと」と「事業の成長」の両方を最もよく表す指標を1つ選ぶ。

| 条件 | 問い |
| --- | --- |
| 顧客価値 | この指標が増えると、顧客は価値を得ているか |
| 事業との連動 | この指標が増えると、売上も増えるか |
| 先行性 | 売上より先に動くか |
| 行動可能性 | チームの施策で動かせるか |

例: 週あたりの成功した判断の数（登録数やView数は顧客価値を表さないので選ばない）。

### 深掘りの問い

* 最も多くの人が離れている段階はどこか。その理由は何か。
* 数値が良く見えているのは、本当の改善か、定義や集計の変化か。
* 顧客が価値を得ていないのに、増えてしまう指標はどれか（それを目標にしてはいけない）。

### 合格ライン

| 浅い | 深い |
| --- | --- |
| 「ユーザー数とSNSの反響を追う」 | 「North Star は週あたりの成功した判断の数。Activation は『自分の入力で最初の判断結果を得た』と定義し、ローンチ後4週間で、Activation 済みと未達の人の30日継続率を比べて定義を検証する。コホートごとの週次継続率を追い、12週目で横ばいになるかを確認する。目標値は仮置きで、最初の8週のデータで見直す」 |

### よくある失敗

* View数や登録数を成功の指標にする。
* Activation の定義を、継続利用との関係で検証しない。
* 全体の数値だけを見て、コホートごとの継続率を見ない。

### 出力

```text
■ Funnel の各段階の定義
■ 段階ごとの指標と目標（根拠と証拠ラベル）
■ 先行指標と遅行指標
■ コホート分析の方法
■ North Star Metric と、その理由
```

### 次への受け渡し

* 指標 → P27（Unit Economics の入力）、P32（実験の指標）

## P27: Business Viability

### 目的

戦略が、事業として成り立つかを数値で確かめる。マーケティングとして魅力的でも、1顧客を獲得するコストが、その顧客から得る利益を上回っていれば、成長するほど赤字が膨らむ。

### 入力

P1の現状の総コスト（顧客にとっての価値の大きさ）、P5のICP、P18の Motion、P19の価格、P26の指標。

### 手順

**Step 1. Unit Economics を計算する**

| 項目 | 計算方法 | 値 | 証拠ラベル |
| --- | --- | --- | --- |
| CAC（顧客獲得コスト） | 獲得にかかった費用（広告、営業、マーケティング）÷ 獲得した顧客数 | | |
| ARPA（顧客あたり売上） | 売上 ÷ 顧客数（月額または年額） | | |
| 粗利率 | （売上 − 提供コスト）÷ 売上 | | |
| 解約率 | 期間中に解約した顧客 ÷ 期首の顧客 | | |
| LTV（顧客生涯価値） | ARPA × 粗利率 ÷ 解約率 | | |
| LTV / CAC | | 目安3以上 | |
| CAC回収期間 | CAC ÷（ARPA × 粗利率） | 目安12〜18か月以内（Motion により異なる） | |

ARPA と解約率は、同じ期間の単位（月次なら両方とも月次）で揃える。CAC回収期間を月数で出す場合は、月次の値を使う。

数値がない場合は、仮置きの数値を使い、その根拠を書く。

**Step 2. Motion ごとに CAC を分けて見る**

PLG と Sales-Led では、CAC の構造がまったく違う。ハイブリッドの場合は分けて計算する。

* PLG の CAC: マーケティング費用 ÷ 有料転換した顧客数
* Sales-Led の CAC: （マーケティング費用＋営業の人件費）÷ 受注した顧客数

**Step 3. 提供コストを確認する**

特にAI製品やインフラ製品では、利用量に比例して提供コスト（計算資源、APIの原価）が増える。利用量が増えたときに粗利率がどう変わるかを確認する。

```text
利用量が10倍になったとき:
売上: ○倍
提供コスト: ○倍
粗利率: ○% → ○%
```

**Step 4. 感度を分析する**

以下の表で、どの前提が変わると結論が変わるかを確認する。

| 前提 | 現在の仮置き | 悲観ケース | 悲観ケースでの LTV/CAC |
| --- | --- | --- | --- |
| 有料転換率 | | | |
| 解約率 | | | |
| ARPA | | | |
| CAC | | | |

悲観ケースで LTV/CAC が1を下回る前提が、**最も重要な前提** である。これをP32で最優先に検証する。

**Step 5. 市場規模をボトムアップで見積もる**

```text
TAM: 対象となる全顧客の数 × 想定ARPA
SAM: 自社の Motion とチャネルで届く顧客の数 × 想定ARPA
SOM: 3〜5年で現実的に獲得できる顧客の数 × 想定ARPA
```

市場レポートの数値（トップダウン）だけを使わない。「AI市場は○兆円」のような数値は、自社が取れる市場の大きさを表さない。

価格が下がることで新しい用途が生まれ、需要全体が増えると主張する場合は、その根拠を示す（過去の類似例、価格を下げたときの利用量の変化のデータなど）。根拠がなければ **[仮説]** とする。

**Step 6. 資金とタイミングを確認する**

* 市場教育（P6で新カテゴリーを選んだ場合）に何か月かかるか。その間の資金は足りるか。
* Sales-Led の場合、セールスサイクルの長さ（数か月〜1年）の間の資金は足りるか。
* 損益分岐に達するまでの期間の見積もり。

**Step 7. 撤退・転換の基準を決める**

以下の状態になったら、戦略を見直す、という基準を事前に決める。

```text
例: ローンチから6か月後に、
    有料転換率が○%を下回る
    または D90 継続率が○%を下回る
    → P5のICPまたはP6の市場定義を見直す
```

**Step 8. 判定する**

```text
事業性: 成立する / 条件付きで成立する（条件: …） / 現時点では成立しない
最も重要な前提:
その前提を検証する方法（P32へ）:
撤退・転換の基準:
```

### 深掘りの問い

* 顧客が増えるほど、1顧客あたりのコストは下がるか、上がるか。
* 最も大きな顧客が解約したら、売上はどれくらい減るか。
* 競合が価格を半分にしたら、粗利率はどうなるか。

### 合格ライン

| 浅い | 深い |
| --- | --- |
| 「市場規模は○兆円なので、1%取れば○億円」 | 「SAM: AI Gateway 経由で届く、Agentを本番運用している企業 約○社 × 想定ARPA 年○万円 = ○億円。PLG の CAC は○万円、LTV/CAC は仮置きで4.2。ただし解約率が月5%を超えると1.8まで下がるため、解約率が最も重要な前提。最初の3か月のコホートで検証する（数値は仮置き）」 |

### よくある失敗

* 市場レポートの大きな数値から「1%取れば○億円」と見積もる。
* PLG と Sales-Led の CAC を混ぜて計算する。
* 利用量が増えたときの提供コストの増加を見ない。
* 楽観的な前提だけで計算し、感度を確認しない。

### 出力

```text
■ Unit Economics の表
■ Motion ごとの CAC
■ 利用量が増えたときの粗利率
■ 感度分析と、最も重要な前提
■ 市場規模（ボトムアップ）
■ 資金とタイミング
■ 撤退・転換の基準
■ 判定
```

### 次への受け渡し

* 最も重要な前提 → P32（最優先の実験）
* 判定 → P31 Reality Check
