# White Space Discovery モード

製品がまだなく、市場・技術領域・顧客課題の中から「勝てる領域」「未開拓な領域」を探すときの手順である。

このモードで最も起きやすい失敗は、**魅力的な候補を1つ思いつき、それを補強する情報だけを集めて「未開拓」と結論すること** である。これを防ぐため、候補を複数出し、すべての候補に同じ基準で先行事例の確認（P0.5）をかけてから、通過した候補だけを深掘りする。

---

## 手順

### Step 1. P0 Intake（探索版）

以下を確認する。必須項目が欠けている場合は、まとめて質問する（1回で最大5問まで）。重要項目が欠けている場合は、仮定を置いて進め、その仮定を明示する（`SKILL.md` 3.1）。

| 区分 | 項目 | 内容 |
| --- | --- | --- |
| 必須 | 探索する範囲 | 市場、技術領域、顧客層のどれを起点にするか。範囲の外にあるもの |
| 必須 | 依頼者の強み・資源・制約 | 技術、データ、顧客との接点、資金、人員、期間 |
| 必須 | 探索の目的 | 新規事業、研究テーマ、投資先の検討、既存事業の隣接領域など |
| 重要 | 判断の基準 | 依頼者にとって「勝てる」とは何か（市場規模、収益化までの期間、社会的意義など） |

### Step 2. 候補領域を出す

候補を5〜8個出す。候補は、**製品のアイデアではなく「顧客 × 問題 × 条件」** の形で書く。製品のアイデアで書くと、その製品を作る前提で調べてしまう。

```text
例: 【顧客】中小規模の物流倉庫の現場責任者が、
    【問題】日々の人員配置を経験と勘で決めていて、
    【条件】繁忙期に欠員が出たときに組み直しが間に合わない
```

候補の出し方:

| 起点 | 問い |
| --- | --- |
| 変化 | 最近起きた技術・コスト・規制・行動の変化で、以前は解けなかった問題が解けるようになっていないか（P15の観点） |
| 顧客の諦め | 対象の顧客が「仕方ない」と受け入れていることは何か（`SKILL.md` 2.3） |
| 依頼者の強み | 依頼者の技術・データ・顧客接点を使うと、他の人より有利に解ける問題は何か |
| 隣接分野 | 別の分野では当たり前に解かれている問題が、この分野では解かれていないことはないか |

1つの起点に偏らないようにする。候補の数を増やすために、似た候補を言い換えて並べない。

### Step 3. すべての候補に P0.5 をかける

`references/stage-a-problem-discovery.md` の P0.5 の手順を、**すべての候補に同じ基準で** 行う。有望に見える候補だけを深く調べ、他の候補を浅く調べると、比較が成り立たない。

候補ごとに、以下を必ず残す。

* 問題の言い換えと検索語
* 確認した情報源の種類と、確認しなかった種類（理由つき）
* 確認した期間と調査日
* 主要な先行事例と、その「解決していること／解決していないこと」（一次資料つき）

### Step 4. 候補ごとに判定する

このモードの判定は、P0.5 の3つの判定（解決済み／部分的に解決済み／先行事例なし）を、探索のために細かく分けたものである。対応は「P0.5 の判定」列のとおり。

| 判定 | 条件 | P0.5 の判定 | 扱い |
| --- | --- | --- | --- |
| **未開拓** | `SKILL.md` 3.4 の基準を満たして調べたうえで、先行事例が見つからなかった。かつ、なぜ誰も解いていないのかの仮説がある（Step 6 の P2 で確かめる） | 先行事例なし | 深掘りの対象 |
| **競合がいる初期段階** | 先行事例はあるが、少数で、まだ市場の標準が決まっていない。解決の水準や対象の顧客に隙間がある | 部分的に解決済み | 深掘りの対象。残る隙間を明記する |
| **部分的に解決済み** | 既存の解決策が主要な顧客の問題を解いているが、特定の顧客・条件・コスト水準では解けていない | 部分的に解決済み | 残る隙間が十分に大きい場合だけ深掘りの対象。隙間を1文で明記する |
| **解決済み** | 既存の解決策が、対象の顧客にとって十分な水準で問題を解いている | 解決済み | 原則として捨てる。捨てない場合は理由を書く |
| **判定不能** | 調べる手段がない、または情報が足りない | 未実施、または 3.4 の基準を満たさない「先行事例なし」 | 深掘りしない。必要な調査を P32 に入れる |

「未開拓」の判定には、[不在確認: 調査範囲] を付ける。基準を満たさない場合は「未開拓」と書かず、「先行事例は見つからなかった（調べた範囲: …）」とし、判定不能として扱う。

### Step 5. 通過した候補を評価して絞る

深掘りの対象になった候補を、以下で評価する。

| 評価軸 | 問い | 点数（1〜5） |
| --- | --- | --- |
| 課題の強さ | 顧客は回避策やお金を使っているか | |
| 隙間の大きさ | 既存の解決策が解いていない部分は、事業になる大きさか | |
| なぜ今か | 最近の変化で、今解けるようになった理由があるか | |
| 依頼者との適合 | 依頼者の強みを使えるか。制約の中で実行できるか | |
| 誰も解いていない理由の説明 | 技術的に難しい、市場が小さい、などの可能性を否定できるか | |

上位1〜3個を選ぶ。

### Step 6. 選んだ候補を深掘りする

選んだ候補ごとに、以下のPhaseを行う。

| Phase | このモードでの焦点 |
| --- | --- |
| P1 Existing World | 顧客が今どうしているか。P0.5 の先行事例のうち、顧客が実際に使っているもの |
| P2 Problem Discovery | 残る隙間の構造原因。なぜ今まで誰も解いていないのか |
| P3 Contrarian Thesis | この領域で、多くの人がまだ気付いていない、証拠のある仮説 |
| P6 Category Decision（判定のみ） | 新カテゴリー／サブカテゴリー／再ポジショニングのどれになりそうか。このモードでは P4・P5 を実行しないため、候補の【顧客】を ICP の【前提】として置く |
| P15 Timing | なぜ今なのか |
| P31 Reality Check | **反証パスを必ず行う。** 選んだ候補を否定する事実を、P0.5 とは別の言い方・情報源で探す |
| P32 Next Experiments | 領域が本当に有望かを確かめる、最初の実験 |

反証パスで前提を覆す事実が見つかった場合は、その候補の判定を Step 4 に戻ってやり直す。

---

## よくある失敗

* 最初に思いついた候補に愛着を持ち、その候補だけを深く調べる。
* 候補を製品のアイデアで書き、その製品を作る前提で調べる。
* 捨てた候補と、その理由を出力に書かない。捨てた理由は、依頼者が後で同じ領域を検討するときの重要な情報である。
* 「未開拓」を、調査の記録なしで断言する。
* 依頼者の言い方でしか調べず、別の用語で存在する解決策を見落とす。
